# Provider deployment and synchronization

Use this reference for V0.8 provider discovery, installation, sync, update,
rollback, or doctor work.

## Invocation contract

- Codex discovers the project skill under `.agents/skills/` and explicitly invokes
  it as `$mt-developer-dna`; do not claim `/mt-developer-dna` support.
- Claude Code discovers `.claude/skills/mt-developer-dna/SKILL.md` and exposes the
  skill as `/mt-developer-dna`.
- Gemini CLI discovers the skill under `.gemini/skills/`; the explicit
  `/mt-developer-dna` shortcut comes from
  `.gemini/commands/mt-developer-dna.toml`. Verify it with `/commands list`.
- Arguments such as `doctor`, `install`, and `sync` are agent requests. They are
  not automatically identical to Rust CLI arguments and never bypass approval.
- Google Antigravity uses `.agents/skills/mt-developer-dna/SKILL.md` for a
  workspace, `.gemini/config/skills/mt-developer-dna/SKILL.md` globally in the
  IDE, and `.gemini/antigravity-cli/skills/mt-developer-dna/SKILL.md` globally
  in the CLI. Discover the CLI as `agy`; on Windows also validate the IDE's
  user-scope installation. A user-selected path must resolve to `agy(.exe)` or
  `Antigravity IDE(.exe)` before it counts as installed.
  Its legacy workflow mechanism is deprecated and must not be generated by default.
- Cursor uses `.cursor/skills/mt-developer-dna/SKILL.md` and supports manual
  `/mt-developer-dna` invocation.
- Cline uses `.cline/skills/mt-developer-dna/SKILL.md` in a project and
  `~/.cline/skills/mt-developer-dna/SKILL.md` globally. Detect its VS Code
  extension by validating the `saoudrizwan.claude-dev` package manifest in the
  standard, Insiders, `VSCODE_EXTENSIONS`, or explicitly selected extension
  root. Physical installation does not prove that the extension is enabled in
  the active VS Code profile.
- OpenCode uses `.opencode/skills/mt-developer-dna/SKILL.md`; set the documented
  `metadata.opencode/slash` value so the skill is exposed as a slash command.
  On Windows discover `opencode.exe`, npm `opencode.cmd`, and npm
  `opencode.ps1` from PATH. Respect PowerShell execution policy; do not bypass
  it merely to obtain a version. Global skills live under
  `~/.config/opencode/skills/`.

## Safe deployment

1. Detect the executable and version. Distinguish not found from a detected but
   unverified capability.
2. Resolve project or global scope and show every target file before writing.
3. Generate the package deterministically and record SHA-256 values, package
   version, schema version, and adapter version.
4. Default to dry-run. Classify each file as create, update, unchanged, or
   conflict. Treat an installed hash differing from the registry as user-modified.
5. Require explicit `--yes` immediately before mutation. An agent invocation is
   not installation consent.
6. Use a transaction lock, backups, temporary files, and same-filesystem atomic
   replacement. Do not back up files that appear to contain credentials.
7. Roll back only the transaction's files. Stop if an installed or backup hash no
   longer matches; do not erase later user work.

## Doctor

Report executable/version, documented invocation, registry and file hashes,
project-memory presence, and backup integrity where available. Live interactive
provider execution is optional and must remain `NOT_RUN` when it was not actually
performed. Do not start a daemon, watcher, or polling loop.
