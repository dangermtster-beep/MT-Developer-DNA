## Antigravity discovery düzeltmesi

- Kök neden: adapter var olmayan `antigravity` komutunu arıyordu; gerçek CLI
  executable adı `agy` idi ve IDE kurulumu hiç taranmıyordu.
- Otomatik Windows keşfi: PATH üzerindeki `agy`, kullanıcı-scope CLI yolu ve
  kullanıcı-scope Antigravity IDE yolu doğrulanır.
- Standart dışı kurulum: tek provider seçiminde `--provider-path` ile executable
  veya kurulum klasörü verilebilir; beklenmeyen dosya adı reddedilir.
- Global hedef: IDE için `.gemini/config/skills`, CLI için
  `.gemini/antigravity-cli/skills`; project hedefi `.agents/skills` olarak korunur.
- Dry-run: otomatik IDE global, açık CLI global ve IDE project planları PASS;
  hiçbir provider dosyasına yazılmadı.
- Sandbox `%LOCALAPPDATA%` değerini izole bir `Packages\sandbox...` yoluna çevirdiği
  için bu değişkenle verilen ilk açık CLI yolu doğrulaması beklendiği gibi reddedildi.
  Kullanıcıya özgü `%LOCALAPPDATA%\agy\bin\agy.exe` yolu ve otomatik
  `%USERPROFILE%` fallback'i ayrı çalıştırmada PASS oldu.

## Cline discovery ve deployment düzeltmesi

- Kök neden: Cline bağımsız CLI olmadığı hâlde discovery yalnız executable
  modeliyle çalışıyor, `executable: None` sonucunu doğrudan kurulu değil sayıyordu.
- Extension kimliği: Visual Studio Marketplace ve kurulu `package.json`
  manifestleri üzerinden `saoudrizwan.claude-dev` olarak doğrulandı.
- Discovery: standart VS Code, VS Code Insiders, `VSCODE_EXTENSIONS` ve
  `--provider-path` ile seçilen özel extension kökleri destekleniyor.
- Güvenlik: klasör adı yeterli sayılmıyor; publisher/name manifest kimliği,
  normal dosya/dizin ve 1 MiB manifest sınırı doğrulanıyor. Tarama 1024 doğrudan
  alt dizinle sınırlı; watcher veya polling eklenmedi.
- Profiller: fiziksel paket deposundaki kurulum algılanıyor. Seçili profilde
  enable/disable durumu paket varlığından çıkarılmıyor ve canlı doğrulama
  yapılmadığı için `NOT_RUN` kalıyor.
- VS Code CLI `code --list-extensions --show-versions` kontrolü sandbox'ın VS Code
  kurulum dizinine `chdir` ve kullanıcı log klasörüne yazmayı engellemesi nedeniyle
  `EPERM` ile çalışmadı. Bu nedenle aktif profil sonucu üretilmedi; doğrulama
  salt-okunur fiziksel paket manifestleriyle sınırlandı.
- Universal Language Profile dry-run: project planı `.cline/skills/` ve
  `.clinerules/`; global plan `%USERPROFILE%\.cline\skills` hedefini üretti.
  Her iki plan `Create` gösterdi ve hiçbir dosyaya yazmadı.

## OpenCode Windows npm discovery düzeltmesi

- Kök neden: `Command::new("opencode")`, PowerShell'in komut çözümlemesini ve npm
  `.cmd`/`.ps1` shim'lerini kullanmadığı için kurulu OpenCode'u göremiyordu.
- Discovery: PATH dizinlerinde `opencode.exe`, `opencode.cmd` ve `opencode.ps1`
  normal, symlink olmayan dosyalar olarak doğrulanıyor.
- Sürüm: doğrulanmış `.exe` doğrudan; `.cmd`, shell metakarakterleri reddedildikten
  sonra `cmd.exe /D /S /C`; `.ps1`, execution policy değiştirilmeden
  `powershell.exe -NoProfile -NonInteractive -File` üzerinden deneniyor.
- Yerel sonuç: `.cmd` sürüm probe'u `1.19.3` ile PASS. `.ps1` execution policy
  nedeniyle `AuthorizationManager` hatası verdi; policy bypass edilmedi ve bu
  shim'in sürümü doğrulanmış sayılmadı.
- Universal Language Profile dry-run: project planı `.opencode/skills/` ile
  `.opencode/mt-developer-dna.md`; global plan `.config/opencode/skills/`
  hedefini üretti. Açık `.ps1` yolu da kurulum olarak doğrulandı; dosya yazılmadı.
